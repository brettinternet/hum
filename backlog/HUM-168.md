Problem: human `hum doctor` prints one `process.executable` line per declaration without naming the process, so `FAIL process.executable process executable is unavailable` does not say which process to fix. `ready.executable` has the same gap.

Evidence (2026-11-17, built from 024ec7e): a three-process manifest printed `PASS process.executable process executable is available` three times. `diagnoseExecutable` (internal/cli/doctor.go:233) puts the name only in `details.process`, which `writeDoctorHumanWithPolicy` does not render.

Outcome: human lines for checks with a `process` detail name it, for example `FAIL process.executable web: process executable is unavailable`.

Non-goals: no new checks; no change to doctor JSON, check names, order, or exit status.
