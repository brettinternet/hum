## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Outcome: the published root `hum.schema.json` stays synchronized with the strict Go manifest parser, and manifests generated by `hum init` opt into editor validation automatically.

Current state: `hum.schema.json` already ships at the repository root and is published at `https://raw.githubusercontent.com/brettinternet/hum/main/hum.schema.json`; `hum.example.yaml` already points at that URL. The missing work is drift protection, generated-manifest integration, and user documentation. Do not move the schema or introduce a second copy.

Scope: verify draft 2020-12 coverage for `version: 1`, `processes`, and every process and readiness key accepted by `internal/project/manifest.go`; preserve the process-name rule, exact-one-of readiness rule, duration constraints, and strict additional-property behavior. Add a dependency-free contract test that compares the schema property sets with the parser accepted-key sets and exercises representative valid and invalid manifests. Make both generated and template `hum init` output start with the published schema directive. Document editor behavior and the rule that the Go parser remains authoritative.

Non-goals: SchemaStore registration; generating the schema from Go types; a `hum schema` subcommand; runtime validation through JSON Schema; moving the existing root schema; or changing manifest semantics.
<!-- SECTION:DESCRIPTION:END -->
