Problem: aggregate `hum status` and `hum list` show `exited` for every terminal record, so a clean exit, a crash, and a crash-looping process waiting to relaunch look the same.

Evidence (2026-11-17, built from 024ec7e): `web` (exit 1) and `flappy` (exit 2, `restart: on-failure`; named status said `relaunching in 1s (attempt 3/5)`) both showed `STATE exited`. The state cell is colored by exit code (`processStateStyle`), but its text omits the code, so it is invisible without color.

Scope:
- Human STATE cell in aggregate `status` and `list` (including `list --all` and `--full`): `exited N` for an exit code, `exited SIGNAME` for a signal-killed exit. Other states are unchanged.
- Human RESTART cell in aggregate `status`: `on-failure N/5` while a relaunch is pending, using the same attempt number as named status, and `on-failure exhausted` after the budget is spent, classified from the snapshot the same way `up` classifies `recovery_exhausted`.
- Existing coloring and table width handling apply unchanged.

Non-goals: no new columns; no change to JSON, MCP, sort order, or named status.
