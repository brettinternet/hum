Problem: after `up` reports `readiness timed out`, `hum status NAME` still says `readiness: starting` with no diagnostic, indefinitely. Users and agents read that as still booting.

Evidence (2026-11-17, built from 024ec7e): `slow` with `ready: {match: "Listening", timeout: 2s}` never printed `Listening`. `up` exited 2 with `slow: readiness timed out`, and `hum status slow --json` later returned `"readiness":"starting","readiness_diagnostic":null`. internal/app/app.go defines only `starting`, `ready`, and `running_unverified`. `startExecutableReadiness` runs exec/http/tcp probes under a daemon deadline equal to the manifest readiness timeout, keeps the last diagnostic, emits a `startup_failure` "readiness timeout" event, and stops. A `match` launch has no daemon deadline: `readinessTracker` observes output until a line matches. The CLI `--timeout` override is client-side only (`orchestrate.ReadinessTimeout`).

Scope (owner decision 2026-11-17: timed_out, late match recovers):
- Add readiness state `timed_out` for a launch whose manifest readiness timeout passes without success, for every method. Aggregate and named status, CLI JSON v1, and MCP status report it with a diagnostic: the last probe diagnostic for exec/http/tcp, and `no output matched within DURATION` for `match`.
- The daemon owns the `match` deadline per launch and emits the same `startup_failure` "readiness timeout" event as probes. The tracker keeps observing; a later matching line moves the launch to `ready` and emits `ready` as today. Probes stay stopped after their deadline.
- A relaunch, restart, or start resets readiness to `starting` as today.
- A CLI `--timeout` longer than the manifest timeout stays a client-side wait: status may show `timed_out` while `up` still waits, and a late `match` still lets `up` succeed. Document this in docs/design.md.
- Human rendering uses the existing failure color for `timed_out`.

Non-goals: no probe retries after the deadline; no health monitoring; no change to `up`/`start`/`restart` exit codes or `after` gating; no restart on timeout.
