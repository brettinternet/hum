Problem: a mistyped process name fails with no hint, although Hum already suggests the closest name for mistyped commands.

Evidence (2026-11-17, built from 024ec7e): `hum logs wbe` in a project declaring `web` printed `supervised process not found: "wbe" in /private/tmp/humdev/proj. Run hum list --all to see every scope.` `hum lst` prints `Did you mean "list"?` through `suggestCommandName` (internal/cli/root.go:804).

Scope:
- Move the edit-distance and unique-prefix rule from internal/cli/root.go into one exported helper in internal/app (new file internal/app/suggest.go). Command suggestions call the same helper; there is no second matcher.
- Daemon lookups: `app.NotFoundError` gains a suggestion computed from retained names in the requested scope only. internal/daemon/wire_protocol.go adds it as `details.suggestion` beside `other_scopes`. MCP already forwards not_found details.
- Definition resolution: CLI and MCP not_found results for an undeclared name (`start`, `up NAME`, `restart`, declared `run`) suggest from the manifest's declarations with the same helper.
- CLI human output appends `Did you mean "web"?`. The suggestion is an additive optional `suggestion` string in not_found error details for CLI JSON v1 and MCP, documented in docs/cli-json-v1.md.

Non-goals: never act on a suggestion or auto-correct; no suggestions across scopes (`other_scopes` guidance stays); no change to error codes, exit status, or the matching rule.

- [ ] `mise exec go -- go test ./internal/mcp -run "Test.*NotFound.*Suggest" -count=1` exits 0 asserting MCP not_found errors for `wbe` carry `details.suggestion` `web` for both a retained session lookup and an undeclared definition.
