Problem: a mistyped process name fails with no hint, although Hum already suggests the closest name for mistyped commands.

Evidence (2026-11-17, built from 024ec7e): `hum logs wbe` in a project declaring `web` printed `supervised process not found: "wbe" in /private/tmp/humdev/proj. Run hum list --all to see every scope.` `hum lst` prints `Did you mean "list"?` through `suggestCommandName` (internal/cli/root.go:804).

Leading direction:
- Reuse the `suggestCommandName` edit-distance and unique-prefix rule through one shared helper; do not add a second matcher.
- Candidates are the requested scope's retained names plus its manifest declarations.
- The CLI appends `Did you mean "web"?` to the not-found message; MCP not_found errors carry the same suggestion. Existing cross-scope guidance (`other_scopes`) stays.

Non-goals: never act on a suggestion or auto-correct; no suggestions across scopes; no change to not_found codes or exit status.

Open questions before todo: compute daemon-side (retained names) or CLI-side (manifest names), or both; whether the suggestion is an additive not_found detail in the wire and MCP error or only message text.
