Problem: multi-process `hum logs` prints each process's retained output as a separate block, so correlating one service's error with what the others were doing at that moment means reading timestamps by hand, and human output has no timestamps.

Evidence (2026-11-17, built from 024ec7e): `hum logs --tail 6` in a three-process project printed every `api` entry, then `db`, then `web`. `aggregateLogsRead` (internal/cli/commands.go:1810) reads and renders one name at a time. Every retained entry already carries `time`. `--follow` already prints live output in arrival order.

Scope: human output for multi-name and no-name `hum logs` without `--follow` reads every name as today, then prints:
1. not-launched and per-name error lines, in name order;
2. all retained entries in timestamp order with the existing `[NAME]` prefixes, ties broken by name, then cursor; a `--match --context` group stays contiguous and is placed by its first entry's time;
3. each name's cursor line, in name order.

Filters, `--tail`, `--since`, `--context`, and byte limits keep applying per name; only the order of human lines changes. Update the "Several names" bullets in docs/design.md.

Non-goals: no global cursor; no change to `--json`, MCP logs, `--follow`, single-name output, or exit status; no new flag.
