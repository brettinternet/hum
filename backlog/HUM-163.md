Problem: human `hum events` renders an exit as a bare `exit`, so `hum events --failed` lists failures without saying how they failed.

Evidence (2026-11-17, built from 024ec7e): `hum events web --failed --full` printed `10:56:00 web exit` and `log_cursor=1`, while `--json` for the same event has `"exit_code":1`. A crash-looping `restart: on-failure` process showed a bare `flappy exit` before every `relaunch_scheduled`. `writeEventsHuman` in internal/cli/events.go renders only `Detail`; exit events carry the code and signal in `ExitCode` and `Signal`.

Outcome: exit events show `code=N` or `signal=NAME` in the DETAIL column, in compact and `--full` output.

Non-goals: no change to event JSON, history storage, `--failed` filtering, colors, or column fitting.
